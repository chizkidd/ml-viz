Where did the KV pool actually go? measured

Stage 5 time-averaged share of the KV memory pool across all four pool budgets. Contiguous slots lock two-thirds or more of the pool as reserved-but-empty padding; paged blocks leave unused capacity genuinely free for incoming requests.

How fast can decode possibly go? published specs + formula

Each decode step reads every weight once plus every sequence's KV cache. Memory bandwidth sets the speed limit until compute saturates; memory capacity sets how many sequences fit.

When does a KV cache even win? measured

Stages 1 & 2 on Tesla T4 (Qwen2.5-0.5B, 128-token prompt). Because eager batch-1 decoding is launch-overhead bound, maintaining a KV cache is actually slower than recomputing the whole sequence for short outputs, crossing over only around 422–488 new tokens.

Tesla T4, same 64-request mixed trace replayed over HTTP. Stage 12 introduced the engine; Stage 13 folded GQA heads (moving 29% of attention bytes), refined buckets, and added eager fallback; Stage 14 replaced the gather copy with an in-place Triton paged-attention kernel.
