TD(λ) and the Deadly Triad

TD learning updates a value estimate toward a guess built from the next estimate. Eligibility traces decide how far back one surprise reaches, and lambda is the dial. The last tab shows what goes wrong when you also approximate values with a function and train on data from a different policy. Everything here is computed live in your browser from small simulations, with fixed random seeds so you can reproduce what you see.

A walker starts in the middle of 19 states and steps left or right. Falling off the left end pays −1, off the right end pays +1, everything else pays 0 (undiscounted). The true value of each state runs from −0.9 to +0.9. All estimates start at 0, so the first surprise happens at the very end of an episode.

The smallest example: w and 2w

Two states share one weight: v(s1) = w and v(s2) = 2w. The only transition we ever see goes from s1 to s2 with reward 0, and we update after each one: w ← w + α(γ·2w − w). The update never touches s2's own error, so nothing pulls w back. Each update multiplies w by 1 + α(2γ − 1).

Baird's counterexample

Seven states and two actions. Dashed jumps to one of states 1 to 6 at random. Solid goes to state 7. All rewards are 0, so every true value is 0. We want to learn the value of the policy that always picks solid, but the data comes from a behaviour policy that picks dashed 6/7 of the time. With linear features, v(si) = 2wi + w8 for states 1 to 6 and v(s7) = w7 + 2w8, so 8 weights describe 7 values and zero error is reachable. Start: w = (1,1,1,1,1,1,10,1), gamma = 0.99.
